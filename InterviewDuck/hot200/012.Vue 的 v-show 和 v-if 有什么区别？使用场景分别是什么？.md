### Vue 的 v-show 和 v-if 有什么区别？使用场景分别是什么？

我从渲染机制、性能、生命周期和使用场景四个维度来回答。

---

**一、渲染机制的本质区别**

- **`v-if` 是“真正”的条件渲染**。值为 `false` 时，元素和它内部的组件、事件监听器、子元素会**完全销毁并从 DOM 中移除**；值为 `true` 时再**重新创建并插入**。

- **`v-show` 只是 CSS 切换**。无论初始值是什么，元素始终会被渲染并保留在 DOM 中，仅仅通过切换 `display: none` 来控制显隐。它不会触发组件的销毁和重建。

---

**二、性能消耗差异**

- **`v-if` 有更高的切换开销**。每次切换都会执行销毁/重建，触发完整的生命周期钩子。如果在条件很少改变的场景下很合适，因为 `false` 的结点完全不参与渲染。

- **`v-show` 有更高的初始渲染开销**。因为不管条件如何，元素一开始就必须渲染出来，但之后切换只是改 CSS，几乎没有额外开销。

---

**三、生命周期的差别**

- **`v-if`** 每次从 `false` 变 `true`，子组件会执行 `created`、`mounted` 等完整生命周期；变 `false` 时执行 `destroyed`，所有状态重置。

- **`v-show`** 子组件一挂载就不再销毁，`created` 和 `mounted` 只执行一次，显隐不影响内部状态。

---

**四、使用场景**

| 场景                                       | 推荐指令 | 原因                                                         |
| ------------------------------------------ | -------- | ------------------------------------------------------------ |
| 需要频繁切换显隐                           | `v-show` | 切换成本极低，不重建 DOM                                     |
| 条件很少改变或只判断一次（如用户登录状态） | `v-if`   | 避免不必要的 DOM 占用，懒加载                                |
| 初始条件大概率是 `false`                   | `v-if`   | 避免初始就渲染隐藏元素                                       |
| 和 `v-else`、`v-else-if` 搭配              | `v-if`   | 只有 `v-if` 支持多分支联动                                   |
| `template` 包裹多元素控制                  | `v-if`   | `v-show` 不能用于 `template`，因为 `template` 不渲染真实 DOM，无法设 `display` |

---

**需要注意的坑**

- `v-if` 和 `v-for` **不建议放在同一级元素上**，因为 `v-for` 的优先级更高。Vue 3 中同级的 `v-if` 甚至会报错。正确的做法是用计算属性先过滤数据，或在 `v-for` 外层包一层 `template` 放 `v-if`。

- 如果业务中需要频繁获取隐藏元素的状态或尺寸，`v-show` 保留 DOM 更方便操作；`v-if` 每次重建相当于给了个“干净”状态，有时反而是优势。
