### 使用 link 和 @import 引用 CSS 的区别

我从加载机制、兼容性、性能和使用场景这几个角度来回答。

---

**一、加载方式不同**

- `<link>` 是 HTML 标签，在 `<head>` 中声明，浏览器解析到时会并行加载 CSS 文件，**不阻塞页面渲染**，但会阻塞渲染树的构建。
- `@import` 是 CSS 语法，写在 CSS 文件或 `<style>` 标签中。浏览器会先下载当前样式表，解析到 `@import` 时再去发起请求，**相当于串行加载**，会延长关键渲染路径。

**典型性能差异：**
- 用 `<link>`：HTML 解析时就能提前发起 CSS 请求，与页面其他资源并行下载。
- 用 `@import`：必须等父样式表下载完才开始请求引用的样式，如果嵌套多层 `@import`，就会形成请求链，白屏时间更久。

---

**二、兼容性不同**

- `<link>` 无兼容性问题，所有浏览器都支持。
- `@import` 是 CSS2.1 引入的，IE5 以下不支持，老旧浏览器会完全忽略，导致样式丢失。现代浏览器都没问题，但仍不如 `<link>` 稳健。

---

**三、功能和支持度不同**

- `<link>` 是单标签，还可以用来指定 `rel="alternate stylesheet"` 提供备选样式、设置 `media` 属性做响应式加载、添加 `favicon` 等，功能更丰富。
- `@import` 纯粹就是引入 CSS 文件，可以在后面跟 `media` 条件，比如 `@import url("print.css") print;`，但功能单一。

---

**四、DOM 可控性不同**

- `<link>` 是 DOM 元素，可用 JavaScript 动态创建、修改 `href` 或 `media` 属性来切换样式或懒加载。
- `@import` 写在 CSS 里，不受 DOM 操作控制，无法用 JS 直接管理。

---

**总结：**

| 维度     | `<link>`                     | `@import`              |
| -------- | ---------------------------- | ---------------------- |
| 加载方式 | 并行加载，性能更好           | 串行加载，影响渲染速度 |
| 兼容性   | 所有浏览器                   | IE5 以下不兼容         |
| 功能     | 丰富，支持备选样式、媒体查询 | 单一，仅引入样式       |
| DOM 控制 | 可用 JS 操作                 | 无法用 JS 控制         |

实际开发中，**优先使用 `<link>` 引入 CSS**，`@import` 常用于模块化 CSS 或预处理器（如 Sass `@import`，但现也推荐用 `@use`）中组合样式文件，生产环境不太适合直接使用原生 CSS 的 `@import`。
