### typeof null 的结果是什么？为什么？

结果是 `"object"`，这是 JavaScript 语言早期的一个经典 bug，一直遗留至今。

---

**现象**

```javascript
typeof null; // "object"
```

按照直觉 `null` 应该返回 `"null"`，但实际返回的是 `"object"`。

---

**原因：历史实现的遗留问题**

这要从 JavaScript 早期的类型判断机制说起。

1. **底层存储方式**  
   在 JS 引擎内部，值用二进制表示，并通过前几位来区分类型。当时规定：
   - `000` 开头代表对象类型
   - `1` 开头代表整数
   - `010` 开头代表浮点数
   - 等等

2. **`null` 的表示**  
   `null` 在内存中表示为**全零**，也就是所有位都是 `0`。它的前几位自然也是 `000`，恰好符合对象类型的标记位。

3. **`typeof` 的判断逻辑**  
   `typeof` 检查值的时候，直接用这个二进制标记位来判断类型。看到 `000` 就认为是对象，于是 `typeof null` 就返回了 `"object"`。

---

**为什么不修复？**

这个 bug 在第一版 JavaScript 里就存在了。后来尝试修复（比如让 `typeof null` 返回 `"null"`），但会导致大量依赖旧行为的现有代码崩溃，浏览器厂商不敢动，就作为兼容性设计遗留下来了。

---

**实际开发中怎么正确判断 `null`？**

因为 `typeof` 对 `null` 不可靠，实践中要单独处理：

```javascript
function isNull(value) {
  return value === null;
}
```

或者更通用的空值判断：

```javascript
if (value === null || value === undefined) {
  // 空值处理
}

// 利用 null == undefined 的特性（松散相等）
if (value == null) {
  // 同时过滤 null 和 undefined
}
```

---

**扩展补充：`typeof` 的坑一览**

| 表达式                | 结果                 |
| --------------------- | -------------------- |
| `typeof null`         | `"object"`           |
| `typeof NaN`          | `"number"`           |
| `typeof []`           | `"object"`           |
| `typeof function(){}` | `"function"`（特殊） |

所以 `typeof` 适合判断基本类型（除了 `null`），对象细分判断还是交给 `Array.isArray`、`Object.prototype.toString.call` 等更精确的方法。
