### 为什么不建议在 Vue 中同时使用 v-if 和 v-for？

这道题我从**优先级问题**、**性能浪费**和**正确替代方案**三个角度来回答。

---

**一、优先级问题**

在 Vue 2.x 中，`v-for` 的优先级高于 `v-if`，这意味着：

```html
<li v-for="item in list" v-if="item.isActive">
  {{ item.name }}
</li>
```

渲染逻辑是：先遍历整个 `list` 生成所有 `item`，然后再对每个 `item` 执行 `v-if` 判断。即使只有 10% 的数据满足条件，也要遍历 100% 的列表并创建虚拟节点，再丢弃 90%。

Vue 3 换成了 `v-if` 优先级更高，同级使用直接报错，因为 `v-if` 先执行时找不到 `v-for` 的循环变量。

---

**二、性能浪费的两层含义**

1. **不必要的循环计算**：每次重新渲染，不管数据是否满足条件，都先全量遍历一遍。数据量大或渲染频繁时，浪费非常明显。

2. **Vue 2.x 中指令的执行顺序混乱**：两个指令写在同一节点上，阅读代码的人需要额外记忆优先级，维护性差，容易出 bug。

---

**三、正确的替代方案**

**方案 1：用计算属性过滤（最佳实践）**

```javascript
computed: {
  activeList() {
    return this.list.filter(item => item.isActive)
  }
}
```

```html
<li v-for="item in activeList" :key="item.id">
  {{ item.name }}
</li>
```

优势：
- 只有满足条件的数据参与遍历
- 计算属性会缓存，依赖不变化时不重新计算
- 逻辑在 JS 里，模板保持纯净

**方案 2：外层包装 `<template>`（条件判断在外）**

当需要判断的是整个列表是否渲染时：

```html
<template v-if="shouldShowList">
  <li v-for="item in list" :key="item.id">
    {{ item.name }}
  </li>
</template>
```

这样如果 `shouldShowList` 是 `false`，连循环都不会执行，避免了无谓的遍历。

**方案 3：把列表移到子组件，用 `v-if` 控制子组件**

如果条件判断非常复杂或涉及组件级逻辑，可以把循环部分拆成子组件，在父级用 `v-if` 控制是否挂载。

---

**一句话总结**

`v-if` 和 `v-for` 同层使用会导致不必要的性能开销和逻辑混乱，应该用计算属性在数据层就完成过滤，让模板只负责简洁渲染。这既符合“逻辑归 JS、模板归 HTML”的分离原则，也能充分利用计算属性的缓存优化。
