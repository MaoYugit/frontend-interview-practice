### 为什么 Vue 中的 data 属性是一个函数而不是一个对象？

这道题的核心在于**组件复用时的数据隔离**，我从根组件、可复用组件和底层原理三个层面来回答。

---

**一、组件如果被复用，对象会共享引用**

Vue 中绝大多数组件都是可复用的。假如 `data` 直接写成一个对象：

```javascript
// 错误示范
const MyComponent = {
  data: {
    count: 0
  }
}
```

那么通过 `new` 或全局注册产生的所有组件实例，都会**共享同一个 `data` 对象的引用**。实例 A 修改了 `count`，实例 B 的 `count` 也会同步改变——这完全违背了组件独立、状态隔离的设计原则。

---

**二、换成函数，每次调用都返回新对象**

正确写法是函数：

```javascript
data() {
  return {
    count: 0
  }
}
```

每次创建组件实例时，Vue 会执行这个函数，拿到一个**全新的数据对象**。每个实例都能在自己的作用域里维护独立的数据，互不影响。

---

**三、根组件特殊，但通常也遵循函数写法**

`new Vue({})` 创建的根实例在整个应用里只有一个，不存在复用的情况，所以可以直接写 `data: { }` 对象。但在脚手架项目里，根组件也是用 `.vue` 单文件写，定义方式依然是 `data()` 返回对象，保持整个项目的统一风格。

---

**四、底层原理简述**

Vue 源码在初始化时（`initData` 方法），会判断传入的 `data` 是函数还是对象：
- 如果是函数，就调用 `getData(data, vm)` 拿到返回值并监听
- 如果是对象，直接使用，并在这个阶段发出警告（非根组件用对象 `data` 会直接报错）

所以本质上，Vue 通过约定 `data` 必须是函数，在实例化那一刻完成了数据副本的创建，保证了每个组件实例都有独立的数据引用。

---

**一句话总结**

`data` 必须是一个函数，是为了确保每个组件实例都持有一份独立的数据拷贝，避免多实例共享同一个数据对象导致的状态污染。根实例虽然可以写对象，但为了统一和清晰，也推荐函数写法。
