### Vue Router 如何配置 404 页面？

我从通配符路由配置、匹配优先级和注意事项几个方面来回答。

---

**一、核心配置方式**

在路由配置数组的**最末尾**，用通配符 `*` 匹配所有未定义的路由：

```javascript
const routes = [
  // ... 所有正常路由
  {
    path: '/',
    component: Home
  },
  {
    path: '/about',
    component: About
  },
  // 放在最后
  {
    path: '/:pathMatch(.*)*',  // Vue Router 4.x 写法
    name: 'NotFound',
    component: () => import('@/views/404.vue')
  }
]
```

Vue Router 3.x（Vue 2）的写法略有不同：

```javascript
{
  path: '*',
  redirect: '/404'
}
// 或
{
  path: '*',
  component: NotFound
}
```

---

**二、匹配原理与优先级**

Vue Router 的路由匹配是**从上到下**的。通配符路由必须放在配置数组的**最后一位**，这样当所有正常路由都匹配不上时，才会命中 404。

如果放在前面，后面的路由永远不会被访问到，因为通配符会拦截所有路径。

---

**三、两种处理方式**

**方式一：直接渲染 404 组件**

保持 URL 不变，直接显示 404 内容：

```javascript
{
  path: '/:pathMatch(.*)*',
  name: 'NotFound',
  component: NotFound
}
```

用户访问 `/xyz`，地址栏还是 `/xyz`，但页面展示 404。

**方式二：重定向到统一 404 路径**

```javascript
{
  path: '/:pathMatch(.*)*',
  redirect: '/404'
},
{
  path: '/404',
  name: 'NotFound',
  component: NotFound
}
```

用户访问任何不存在的路径，URL 都会变成 `/404`。优势是便于统计埋点，缺点是不保留用户实际访问的错误路径。

---

**四、Vue Router 4.x 通配符写法变化**

Vue Router 4 必须使用带参数的自定义正则写法：

```javascript
path: '/:pathMatch(.*)*'
```

- `:pathMatch` 是参数名，可在组件内通过 `$route.params.pathMatch` 获取错误路径
- `(.*)` 是正则，匹配任意字符
- 最后的 `*` 表示可重复，匹配多层嵌套路径

如果写成 `'*'` 会直接报错，这是 Vue Router 4 引入的破坏性变更。

---

**五、注意事项**

- 404 页面应该保持轻量，避免首屏加载过重
- 配合路由懒加载：`component: () => import('@/views/404.vue')`
- 服务端最好也返回 404 状态码，否则搜索引擎会索引错误页面。如果用 SPA 部署，Nginx 配置 `try_files` 时要注意统一返回 `index.html`，HTTP 状态码通常仍是 200，需要 SSR 或中间件来处理

---

**完整示例（Vue Router 4）**

```javascript
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/', component: Home },
    { path: '/about', component: About },
    {
      path: '/:pathMatch(.*)*',
      name: 'NotFound',
      component: () => import('@/views/404.vue')
    }
  ]
})
```
