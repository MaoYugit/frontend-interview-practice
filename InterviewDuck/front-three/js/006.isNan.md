isNaN 和 Number.isNaN 函数有什么区别？

`isNaN` 和 `Number.isNaN` 是 JavaScript 中用于检测一个值是否为 `NaN`（Not a Number）的两个函数，它们的核心区别在于**是否进行隐式类型转换**。

以下是具体的对比和分析：

### 1. 全局的 `isNaN` 函数

全局的 `isNaN` 方法在设计上存在一定的历史局限性。它的执行逻辑如下：

1. **隐式转换**：先尝试将传入的参数通过类似 `Number()` 的规则转换为数值类型。
2. **判断**：如果转换后的结果是 `NaN`，则返回 `true`；否则返回 `false`。

由于它会进行类型转换，导致许多**本不是 `NaN` 但无法转换为有效数值的值**也会返回 `true`，这在逻辑上常常会引发混淆。

**示例：**

```javascript
isNaN(NaN); // true
isNaN(undefined); // true （因为 Number(undefined) 是 NaN）
isNaN("hello"); // true （因为 Number('hello') 是 NaN）
isNaN({}); // true （因为 Number({}) 是 NaN）

isNaN(123); // false
isNaN("123"); // false （因为 '123' 可以被转换为数字 123）
isNaN(true); // false （因为 Number(true) 是 1）
isNaN(null); // false （因为 Number(null) 是 0）
```

---

### 2. `Number.isNaN` 方法

为了解决全局 `isNaN` 的上述缺陷，ES6（ES2015）引入了 `Number.isNaN` 方法。它的执行逻辑非常严谨：

1. **类型检查**：先检查传入参数的类型是否为 `Number`。如果不是，直接返回 `false`。
2. **值检查**：如果类型是 `Number`，再判断其值是否为 `NaN`。

也就是说，只有当参数**严格等于 `NaN`**（且类型为数字）时，它才会返回 `true`。它不会对参数进行任何隐式的类型转换。

**示例：**

```javascript
Number.isNaN(NaN); // true

Number.isNaN("hello"); // false （类型是 String，直接返回 false）
Number.isNaN(undefined); // false （类型是 Undefined，直接返回 false）
Number.isNaN({}); // false （类型是 Object，直接返回 false）
Number.isNaN("123"); // false
```

---

### 3. 对比总结

| 特性               | 全局 `isNaN`                           | `Number.isNaN`              |
| :----------------- | :------------------------------------- | :-------------------------- |
| **引入版本**       | ES1 (原生全局方法)                     | ES6 (ES2015)                |
| **隐式类型转换**   | **会**进行转换                         | **不会**进行转换            |
| **判断逻辑**       | 是否能被转换为数值（若不能则为 `NaN`） | 是否是值为 `NaN` 的数值类型 |
| `isNaN(NaN)`       | `true`                                 | `true`                      |
| `isNaN('abc')`     | `true` (因为无法转为数字)              | `false` (因为它是字符串)    |
| `isNaN(undefined)` | `true`                                 | `false`                     |

---

### 4. 垫片（Polyfill）实现

在不支持 ES6 的旧环境中，`Number.isNaN` 的逻辑可以通过以下两种方式来实现：

**方法一：利用类型判断和全局 `isNaN`**

```javascript
if (!Number.isNaN) {
  Number.isNaN = function (value) {
    return typeof value === "number" && isNaN(value);
  };
}
```

**方法二：利用 `NaN` 是 JavaScript 中唯一一个“不等于自身”的值的特性**

```javascript
if (!Number.isNaN) {
  Number.isNaN = function (value) {
    return value !== value;
  };
}
```

### 建议

在现代 JavaScript 开发中，为了避免因隐式类型转换导致的意外错误，**推荐优先使用 `Number.isNaN`** 来进行精确的 `NaN` 判断。

---

在 JavaScript（以及遵循 IEEE 754 浮点数标准的其他编程语言）中，**`NaN`** 是 **"Not a Number"** 的缩写，意为**“非数值”**。

它是一个特殊的数值，用来表示**一个本应返回数值、但由于计算错误或无意义导致无法用正常数字表示的结果**。

以下是关于 `NaN` 的几个核心特征：

### 1. 最大的悖论：它的类型是“数字”

虽然 `NaN` 的字面意思是“不是一个数字”，但它在 JavaScript 中的数据类型恰恰就是 `Number`。

```javascript
console.log(typeof NaN); // "number"
```

### 2. 什么情况下会产生 `NaN`？

通常在以下几种非法的或无法得出确切数字的数学运算中，会产生 `NaN`：

- **无法解析的类型转换**：尝试将非数字的字符串或不适用的类型强制转换为数字。
  ```javascript
  Number("hello"); // NaN
  parseInt("abc"); // NaN
  ```
- **无意义的数学计算（数学上未定义的结果）**：
  ```javascript
  0 / 0; // NaN
  Infinity - Infinity; // NaN
  Math.sqrt(-1); // NaN （负数开平方）
  ```
- **与 `undefined` 的算术运算**：
  ```javascript
  5 + undefined; // NaN
  ```
- **`NaN` 的传播**：任何与 `NaN` 进行的算术运算，结果依然是 `NaN`。
  ```javascript
  NaN + 5; // NaN
  NaN * 0; // NaN
  ```

### 3. 特殊属性：它不等于任何值（包括它自己）

`NaN` 在 JavaScript 中有一个独一无二的特性：**它是唯一一个不等于自身的值**。

```javascript
console.log(NaN === NaN); // false
console.log(NaN == NaN); // false
```

正因为这个特性，我们不能用普通的等于号 `==` 或严格等于号 `===` 来判断一个值是否为 `NaN`，而必须借助 `Number.isNaN()` 或 `isNaN()` 函数：

```javascript
let result = Number("hello"); // 结果是 NaN

// 错误写法
if (result === NaN) { ... } // 永远不会执行

// 正确写法
if (Number.isNaN(result)) { ... } // 可以正常判断
```

### 总结

可以把 `NaN` 理解为程序计算中的一个**“报错占位符”**。当程序做了一次失败的数学运算，但又不能直接让整个程序崩溃中断时，它就会返回 `NaN` 来告诉你：“这次计算没有得到有意义的数字”。
