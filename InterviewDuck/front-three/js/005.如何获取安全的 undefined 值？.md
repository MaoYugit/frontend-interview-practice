如何获取安全的 undefined 值？

在 JavaScript 中，获取一个“安全”的 `undefined` 值是一个经典的问题。

之所以会存在“不安全”的 `undefined`，是因为 **`undefined` 在 JavaScript 中不是保留关键字**（这与 `null` 不同），它只是全局对象上的一个属性。

虽然在现代 JavaScript（ES5 及之后）中，全局的 `undefined` 已经被设置为了只读属性，无法被修改，但是在**局部作用域**中，它依然可以被重新声明和遮蔽（Shadowing）：

```javascript
function test() {
  const undefined = "oops, broken!"; // 局部作用域内遮蔽了全局的 undefined
  console.log(undefined); // 输出 "oops, broken!"
}
```

为了防止这种由于局部遮蔽或历史遗留环境导致的风险，开发者通常会采用以下几种方法来获取安全的 `undefined`：

---

### 方法一：使用 `void 0`（最推荐、最常用）

`void` 是 JavaScript 的一个一元运算符，它的核心作用是**计算其后的表达式，并无条件返回纯净的 `undefined` 值**。

```javascript
const myUndefined = void 0;
// 或者是 void 1, void (expression) 等，因为它们都返回原生的 undefined
```

- **优点**：
  - **绝对安全**：`void` 是保留关键字，无法被开发者重新定义或遮蔽，因此 `void 0` 永远返回最纯净的 `undefined`。
  - **节省空间**：`void 0` 仅占 6 个字符，而 `undefined` 占 9 个字符。各大打包压缩工具（如 Terser、Babel）在混淆压缩代码时，默认会将所有的 `undefined` 替换为 `void 0`。

---

### 方法二：声明未初始化的本地变量

在 JavaScript 中，任何声明了但未被赋值的变量，其默认值都是 `undefined`。可以利用这一特性，声明一个干净的局部变量来获取：

```javascript
function getSafeUndefined() {
  let undef; // 未初始化
  return undef; // 必然返回真实的 undefined
}

const myUndefined = getSafeUndefined();
```

- **优点**：代码可读性好，完全符合语言本身的运行机制。

---

### 方法三：IIFE 缺省形参（历史经典手法）

在早期的第三方库（如旧版 jQuery）中，为了确保代码在各种恶劣、未知的宿主环境下都能安全运行，经常会采用立即执行函数（IIFE），并故意在形参列表的最后多留一个 `undefined`，但在调用时不传入实参：

```javascript
(function (window, undefined) {
  // 在这个闭包里，因为没有传入第二个参数，
  // 所以局部变量 undefined 必定是真正的 undefined 值
  console.log(undefined);
})(window /* 故意不传第二个参数 */);
```

- **优点**：能保证整个闭包内的 `undefined` 都是安全且可以作为标准变量名使用的。
- **缺点**：在如今的模块化开发（ES Modules）中，这种写法已经逐渐淡出舞台。

---

### 补充：如果目的是为了“安全判断”

如果你不需要获取 `undefined` 变量，而只是想**安全地判断一个变量是否是 `undefined`**，最推荐的方式是使用 `typeof` 运算符。

因为 `typeof` 不仅不怕 `undefined` 被局部遮蔽，而且**即使变量根本没有被声明（未定义），它也不会抛出 `ReferenceError` 错误**，而是安全地返回字符串 `"undefined"`。

```javascript
// 假设 someVar 根本没有被声明过
if (typeof someVar === "undefined") {
  console.log("someVar 确实未定义");
}
```
