为什么 JavaScript 中 0.1 + 0.2 !== 0.3，如何让其相等？

---

在 JavaScript 中，`0.1 + 0.2 !== 0.3` 是一个经典问题，其根本原因在于**计算机底层对浮点数的存储和计算方式**。

---

### 一、 为什么 `0.1 + 0.2 !== 0.3`？

#### 1. 进制转换导致的“无限循环”

在数学中，我们使用的是十进制。但在计算机底层，所有数据都必须转换为**二进制**进行存储和计算。

- 在十进制中，像 $\frac{1}{3}$（$0.3333...$）是一个无限循环小数，无法用有限的十进制位数精确表示。
- 同理，在二进制中，许多十进制的有限小数（如 $0.1$ 和 $0.2$）无法用有限的二进制位数精确表示，它们会变成**无限循环小数**：
  - $0.1 \rightarrow 0.00011001100110011001100110011001100110011001100110011001..._2$
  - $0.2 \rightarrow 0.00110011001100110011001100110011001100110011001100110011..._2$

#### 2. 存储精度的限制（IEEE 754 标准）

JavaScript 遵循 **IEEE 754 标准**，使用 **双精度浮点数（Double Precision）** 来表示数字，每个数字固定占用 64 位（bit）的存储空间。
其中，用于表示有效数字（尾数）的空间只有 52 位。

由于存储空间有限，无限循环的二进制小数在存储时必须被**截断（或舍入）**。这种截断导致了精度的丢失：

- $0.1$ 在计算机中实际存储的值约为：`0.10000000000000000555111512312578...`
- $0.2$ 在计算机中实际存储的值约为：`0.20000000000000001110223024625156...`

#### 3. 累加后的结果

当计算机将这两个带有微小误差的数字相加时，误差会被放大。两数相加在二进制中完成并转换回十进制后，结果变成了：

```javascript
0.1 + 0.2; // 0.30000000000000004
```

由于 `0.30000000000000004 !== 0.3`，因此两者的比较结果为 `false`。

---

### 二、 如何解决这个问题（让其相等）？

在实际开发中，有几种常用的方法来解决浮点数计算误差：

#### 方法 1：使用 `Number.EPSILON`（推荐用于数学比较）

`Number.EPSILON` 是 ES6 引入的一个极小的常量（约等于 $2.22 \times 10^{-16}$），它代表 JavaScript 能够表示的最小精度差值。
如果两个数字的差的绝对值小于 `Number.EPSILON`，我们就可以认为它们在数学上是相等的。

```javascript
function numbersCloseEnoughToEqual(n1, n2) {
  return Math.abs(n1 - n2) < Number.EPSILON;
}

console.log(numbersCloseEnoughToEqual(0.1 + 0.2, 0.3)); // true
```

#### 方法 2：转换为整数计算（乘倍数法）

浮点数计算会产生误差，但**整数计算在安全整数范围内是绝对精确的**。
我们可以先将浮点数乘以 10 的幂，转换成整数进行加减，计算后再除回去。这种方法非常适合用于简单的货币计算（如把“元”转为“分”再计算）。

```javascript
// 将 0.1 和 0.2 都乘以 10 变成整数，再除以 10
const result = (0.1 * 10 + 0.2 * 10) / 10;

console.log(result === 0.3); // true
```

_注意：对于更复杂、位数不确定的小数，需要动态计算要乘以多少倍。_

#### 方法 3：使用 `toFixed()` 限制小数位数

`toFixed(n)` 方法可以将数字转换为保留 `n` 位小数的字符串，然后再通过 `parseFloat` 转换回数字。这会自动对多余的精度进行四舍五入。

```javascript
const sum = (0.1 + 0.2).toFixed(12); // "0.300000000000"
const result = parseFloat(sum); // 0.3

console.log(result === 0.3); // true
```

#### 方法 4：使用专业的数学/高精度库（适用于金融或复杂计算）

在开发涉及财务、科学计算等对精度要求极高的项目时，手动处理非常容易出错，建议直接使用成熟的第三方高精度库。这些库在底层使用高精度的自定义算法替代了原生的浮点数运算：

- **`big.js`** / **`bignumber.js`**（轻量，推荐用于金融计算）
- **`decimal.js`**（功能强大，支持三角函数、对数等）
- **`mathjs`**（功能最全的数学库）

**使用示例（以 `big.js` 为例）：**

```javascript
import Big from "big.js";

const x = new Big(0.1);
const y = new Big(0.2);
const result = x.plus(y); // 得到一个 Big 对象

console.log(result.eq(0.3)); // true（使用 .eq() 方法比较）
console.log(result.toNumber()); // 0.3（转换为原生数字）
```
