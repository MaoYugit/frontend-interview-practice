### 一、 1xx 信息性状态码（较少问，但属于加分项）

1xx 状态码表示请求已被接受，需要继续处理。

- **`101 Switching Protocols` (协议切换)**
  - **面试场景**：**WebSocket 连接建立过程**。
  - **深度解析**：客户端通过 HTTP 发送升级请求（带有 `Upgrade: websocket` 请求头），服务器同意升级后会返回 `101`，随后连接正式转换为双向通信的 WebSocket 协议。

---

### 二、 2xx 成功状态码（基础必问）

2xx 表示请求已成功被服务器接收、理解并接受。

- **`200 OK` (成功)**
  - 最常见的成功状态。表示请求的数据正常返回。
- **`201 Created` (已创建)**
  - **面试场景**：RESTful API 规范。
  - **深度解析**：常用于 `POST` 请求。当客户端成功创建了一个新资源（如注册用户成功、发表文章成功），服务器应当返回 `201`。
- **`204 No Content` (无内容)**
  - **面试场景**：`OPTIONS` 预检请求、`DELETE` 请求。
  - **深度解析**：请求成功处理，但响应报文中**不包含实体主体**。常用于跨域请求中的 `OPTIONS` 预检（Preflight），或者一些不需要返回任何数据的 `DELETE` 操作。
- **`206 Partial Content` (部分内容)**
  - **面试场景**：**断点续传、大文件分片下载、视频/音频播放**。
  - **深度解析**：表示服务器成功处理了部分 `GET` 请求。客户端通过请求头 `Range: bytes=0-1024` 指定范围，服务器返回该范围的数据并附带 `206` 状态码，配合响应头 `Content-Range` 使用。

### 三、 3xx 重定向状态码（面试重灾区，必考 🌟）

3xx 表示客户端需要采取进一步的操作才能完成请求。

- **`301 Moved Permanently` (永久重定向)**
  - **面试场景**：网站域名变更、SEO 权重转移。
  - **深度解析**：资源已被永久分配了新的 URL。**浏览器会缓存此重定向关系**，下次访问旧地址时，浏览器不再请求服务器，而是直接从缓存跳转到新地址。
- **`302 Found` (临时重定向)**
  - **面试场景**：临时活动页面、未登录拦截跳转。
  - **深度解析**：资源临时移动。**浏览器不会缓存此重定向**。
  - _历史痛点_：规范规定不准改变请求方法，但早期的浏览器实现中，如果原请求是 `POST`，收到 `302` 后常会自作主张改成 `GET` 去请求新 URL。
- **`303 See Other` (参见其他)**
  - **深度解析**：在 HTTP/1.1 中引入，专门用于解决 302 的混淆。它**明确规定**：客户端应使用 `GET` 方法定向获取新资源（即使原请求是 `POST`）。
- **`304 Not Modified` (未修改)**
  - **面试场景**：**协商缓存**。
  - **深度解析**：如前所述，表示客户端发送了附带条件（`If-None-Match` 或 `If-Modified-Since`）的请求，服务器证实资源未改变，直接让客户端使用本地缓存。
- **`307 Temporary Redirect` (临时重定向)**
  - **面试场景**：与 302 进行对比。
  - **深度解析**：也是临时重定向，但在 HTTP/1.1 中明确规定：**不允许客户端将 `POST` 请求改为 `GET`**。必须保持原请求方法和请求体发送到新地址。
- **`308 Permanent Redirect` (永久重定向)**
  - **深度解析**：与 301 类似，但它在 HTTP/1.1 中明确规定：必须保持原请求方法不变（如果是 `POST` 依然用 `POST` 重定向）。

> **💡 面试经典提问：`301` 和 `302` 有什么区别？对 SEO 有何影响？**
>
> - **301（永久）**：浏览器会缓存，搜索引擎（如 Google、百度）会把旧 URL 的 SEO 权重转移到新 URL 上。
> - **302（临时）**：浏览器不缓存，SEO 权重不会转移，搜索引擎仍会收录旧 URL。如果长期用 302 可能会被搜索引擎误判为垃圾网站。

### 四、 4xx 客户端错误状态码（高频必问）

4xx 表示客户端发送的请求存在错误，妨碍了服务器的处理。

- **`400 Bad Request` (坏请求)**
  - **面试场景**：前后端联调参数格式不匹配。
  - **深度解析**：客户端请求的语义或语法有误，服务器无法解析（例如：前端用 `POST` 发送 JSON，但格式少了个括号，或者字段类型不匹配）。
- **`401 Unauthorized` (未授权)**
  - **面试场景**：用户未登录或 Token 失效。
  - **深度解析**：当前请求需要用户验证。常用于缺少身份验证凭证（如 `Authorization` 请求头）或 Token 已经过期的情况。
- **`403 Forbidden` (拒绝访问)**
  - **面试场景**：**权限控制（RBAC/ABAC）、IP 黑名单、防盗链**。
  - **深度解析**：服务器理解了请求，但是**拒绝执行**。通常与登录状态无关，而是由于该用户没有该接口的访问权限（例如：普通用户尝试调用管理员接口），或者服务器触发了防盗链、安全防火墙。
- **`404 Not Found` (未找到)**
  - 表示服务器上没有找到请求的资源。
- **`405 Method Not Allowed` (方法不允许)**
  - **面试场景**：请求方式错误。
  - **深度解析**：请求的 URL 支持其他方法，但不支持你当前使用的方法。例如：某接口只支持 `POST`，但前端写成了 `GET` 请求，服务器就会返回 `405`。
- **`409 Conflict` (冲突)**
  - **面试场景**：并发修改、唯一键冲突。
  - **深度解析**：请求在服务器端引发了资源冲突。例如：在注册用户时输入了已存在的用户名，或者在多版本控制中提交了版本过旧的代码。

### 五、 5xx 服务器错误状态码（高频必问 🌟）

5xx 表示服务器在处理请求的过程中发生了错误。

- **`500 Internal Server Error` (服务器内部错误)**
  - **面试场景**：后端代码崩溃。
  - **深度解析**：服务器遇到了一个未预料到的状况，导致它无法完成请求。通常是**后端代码中抛出了未捕获的异常/死循环/内存溢出**。
- **`502 Bad Gateway` (坏网关)**
  - **面试场景**：**Nginx 架构分析**。
  - **深度解析**：作为网关或代理的服务器（如 Nginx），从上游服务器（如 Node.js、Go、Java 服务）接收到了一个无效的响应。
  - _常见原因_：上游应用服务器**根本没有启动**、或者由于崩溃**进程挂掉了**（端口无法连接）。
- **`503 Service Unavailable` (服务不可用)**
  - **面试场景**：高并发、限流、服务器升级维护。
  - **深度解析**：服务器目前无法使用（由于超载或停机维护）。通常是临时的状态。
- **`504 Gateway Timeout` (网关超时)**
  - **面试场景**：Nginx 超时配置、慢查询。
  - **深度解析**：作为网关或代理的服务器（如 Nginx）在等待上游服务器返回响应时**超时**了。
  - _常见原因_：上游应用服务器运行正常，但某个请求**处理时间太长**（例如数据库慢查询、复杂的算法处理），超出了 Nginx 配置的 `proxy_read_timeout`。

> **💡 面试经典提问：`502` 和 `504` 有什么区别？**
>
> - **502（Bad Gateway）**：网关找到了后端，但后端**挂了、死掉了或拒绝连接**（回应了无效内容或无法连接）。
> - **504（Gateway Timeout）**：网关找到了后端，后端也活着在处理，但是**处理得太慢了**，网关等不及了（超时）。
