## 实现最基础的 reactive 函数

在这一步，我们正式开始编写 Vue 3 响应式系统的核心 API —— `reactive`。

我们将基于前面学到的 `Proxy` 与 `Reflect`，实现一个最基础的 `reactive` 函数。为了让代码职责更清晰，我们会把 `Proxy` 的处理器（Handlers）抽离出来。

在这个基础版本中，我们先用 `console.log` 作为**占位符**，标出后续进行“依赖收集（track）”和“触发更新（trigger）”的具体位置。

---

### 1. 核心代码实现

新建一个 `reactive.js` 文件（或者在你的 HTML 脚本中）：

```javascript
// 辅助函数：判断是否为对象
function isObject(val) {
  return val !== null && typeof val === 'object';
}

// 抽离 Proxy 的处理器配置
const mutableHandlers = {
  get(target, key, receiver) {
    // 【核心占位】：这里是后续进行“依赖收集（track）”的地方
    console.log(`[track 占位] 属性 "${key}" 被读取，准备收集依赖`);

    // 使用 Reflect 确保 get 操作的 this 指向代理对象
    const res = Reflect.get(target, key, receiver);
    return res;
  },

  set(target, key, value, receiver) {
    // 先获取旧值，用于判断数据是否真的发生了变化（避免无意义的触发更新）
    const oldValue = target[key];
    
    // 使用 Reflect 进行属性赋值，并获取赋值结果（true/false）
    const result = Reflect.set(target, key, value, receiver);

    // 如果新值和旧值不相等，说明数据改变了
    if (oldValue !== value) {
      // 【核心占位】：这里是后续进行“触发更新（trigger）”的地方
      console.log(`[trigger 占位] 属性 "${key}" 被修改，旧值: ${oldValue}, 新值: ${value}。准备派发更新`);
    }

    return result;
  }
};

/**
 * 创建响应式对象
 * @param {Object} target 目标原始对象
 * @returns {Proxy} 代理对象
 */
export function reactive(target) {
  // reactive 只能代理对象类型
  if (!isObject(target)) {
    console.warn(`value cannot be made reactive: ${String(target)}`);
    return target;
  }

  // 返回 Proxy 代理实例
  return new Proxy(target, mutableHandlers);
}
```

---

### 2. 编写测试用例验证

我们可以通过一个简单的脚本来验证这个最基础的 `reactive` 是否能够正常工作：

```javascript
// 测试数据
const state = reactive({
  name: 'Vue 3',
  count: 1
});

// 1. 测试读取属性（触发 get 拦截）
console.log('--- 开始读取数据 ---');
const name = state.name; 
// 预期控制台输出: [track 占位] 属性 "name" 被读取，准备收集依赖

// 2. 测试修改属性（触发 set 拦截）
console.log('\n--- 开始修改数据 ---');
state.count = 2;
// 预期控制台输出: [trigger 占位] 属性 "count" 被修改，旧值: 1, 新值: 2。准备派发更新

// 3. 测试非对象参数
console.log('\n--- 测试非对象参数 ---');
const rawNum = reactive(100); 
// 预期控制台警告: value cannot be made reactive: 100
```

---

### 3. 这个基础版实现了什么？

在这个最基础的 `reactive` 函数中，我们完成了以下三点：
1.  **参数校验**：确保只有对象（Object, Array 等）才会被 Proxy 代理，原始值则直接返回。
2.  **成功拦截**：对对象的读取和写入行为进行了全面的拦截。
3.  **Reflect 绑定**：结合上一节的知识，使用 `Reflect` 保证了即使对象内部存在 `this` 调用，也不会丢失拦截。

现在，骨架已经搭建完毕。接下来我们将进入 **第二阶段的第二部分：理解什么是 effect（副作用函数）**。有了 `effect`，我们才能真正把“数据读取/修改”与“页面/代码更新”串联起来。

## 理解 effect（副作用函数）

在第二阶段，我们来攻克 Vue 3 响应式系统中的另一个核心支柱 —— **`effect`（副作用函数）** 以及用于追踪它的全局变量 **`activeEffect`**。

---

### 一、 什么是副作用函数（Effect）？

在编程中，“副作用”指的是**一个函数的运行改变了外部的状态**。
在 Vue 3 中，`effect` 是一个高阶函数，它接收一个用户自定义的函数 `fn`。
*   当 `fn` 执行时，如果读取了响应式数据，Vue 会自动把 `fn` 收集起来。
*   当这些响应式数据发生变化时，Vue 会自动重新执行 `fn`。

最典型的一个副作用场景就是 **渲染更新 DOM**：
```javascript
// 这是一个 effect，它的副作用是修改了网页的 innerHTML
effect(() => {
  document.body.innerText = state.count; 
});
```

---

### 二、 为什么需要全局变量 `activeEffect`？

在上一节实现的 `reactive` 中，当读取 `state.count` 时，Proxy 的 `get` 拦截器会被触发：
```javascript
get(target, key, receiver) {
  // 我们知道属性被读取了，但如何知道是“哪一个函数”读取了它？
  // get 拦截器的入参中，并没有携带当前正在运行的函数。
}
```
为了打破这个信息壁垒，我们需要引入一个**全局指针 `activeEffect`**。
它的工作原理像是一个临时登记本：
1.  在执行副作用函数之前，我们把这个函数赋值给全局变量 `activeEffect`。
2.  接着运行该副作用函数。此时函数内部读取了响应式数据，触发了 Proxy 的 `get`。
3.  在 `get` 拦截器中，我们只需要去读取全局变量 `activeEffect`。如果 `activeEffect` 有值，就说明**当前读取数据的行为发生在该副作用函数的执行周期内**，于是顺利完成依赖收集（把 `activeEffect` 记录在数据的依赖清单里）。
4.  函数执行完毕后，将 `activeEffect` 重置为 `null`（或上一个副作用函数）。

---

### 三、 实现最基础的 `effect` 与 `activeEffect`

下面是具体实现。为了保证能正确处理**嵌套 effect** 的情况（例如 Vue 中父子组件嵌套渲染，即 ParentEffect 嵌套 ChildEffect），我们在执行时会安全地保存并恢复上一个 activeEffect。

```javascript
// 声明全局变量，用于存储当前正在执行的副作用函数
export let activeEffect = null;

/**
 * 核心 effect 函数
 * @param {Function} fn 用户传入的需要响应式运行的函数
 */
export function effect(fn) {
  // 创建一个包裹函数
  const effectFn = () => {
    let lastEffect = activeEffect; // 支持嵌套：保存上一个正在运行的 activeEffect
    try {
      activeEffect = effectFn;     // 1. 将全局指针指向当前包裹函数
      return fn();                 // 2. 运行用户函数（此期间访问响应式属性将触发 get 并读取 activeEffect）
    } finally {
      activeEffect = lastEffect;   // 3. 执行完毕后恢复上一个 activeEffect（如果无嵌套则恢复为 null）
    }
  };

  // 默认立即执行一次，以触发首次的依赖收集
  effectFn(); 

  return effectFn;
}
```

### 四、 结合前面的 `reactive` 进行测试

现在，我们可以把第一阶段实现的 `reactive` 与刚刚编写的 `effect` / `activeEffect` 组合在一起，观察一下它们是如何协同工作的。

#### 1. 稍微改造一下之前的 `reactive.js`（导入 `activeEffect`）
```javascript
import { activeEffect } from './effect.js'; // 假设它们在同级目录

const mutableHandlers = {
  get(target, key, receiver) {
    // 检查当前是否有 activeEffect 正在运行
    if (activeEffect) {
      console.log(`[track 成功] 检测到活动 effect！开始收集属性 "${key}" 的依赖`);
    } else {
      console.log(`[track 跳过] 属性 "${key}" 被读取，但当前无活动 effect，不收集依赖`);
    }

    return Reflect.get(target, key, receiver);
  },
  
  set(target, key, value, receiver) {
    const oldValue = target[key];
    const result = Reflect.set(target, key, value, receiver);

    if (oldValue !== value) {
      console.log(`[trigger 占位] 属性 "${key}" 变更为: ${value}，准备通知依赖更新`);
    }
    return result;
  }
};
```

#### 2. 编写验证代码
```javascript
import { reactive } from './reactive.js';
import { effect } from './effect.js';

const state = reactive({ count: 10 });

console.log('--- 1. 在 effect 外部读取数据 ---');
const temp = state.count; 
// 预期输出: [track 跳过] ...

console.log('\n--- 2. 定义并运行 effect ---');
effect(() => {
  console.log(`>>> effect 开始执行，读取 state.count 的当前值: ${state.count}`);
});
// 预期输出:
// >>> effect 开始执行，读取 state.count 的当前值: ...
// [track 成功] 检测到活动 effect！开始收集属性 "count" 的依赖

console.log('\n--- 3. 修改响应式数据 ---');
state.count = 20;
// 预期输出:
// [trigger 占位] 属性 "count" 变更为: 20，准备通知依赖更新
```

至此，我们已经完成了：
1.  **数据的代理拦截（`reactive`）**：负责监听数据的读写。
2.  **副作用函数的执行与全局标记（`effect` & `activeEffect`）**：负责明确当前哪个逻辑需要和数据进行绑定。

目前拦截器已经能成功识别出“哪个 effect 访问了哪个数据”。下一步，我们将正式实现 **第三阶段：依赖收集与触发（track 与 trigger）**，用真实的数据结构把它们紧紧锁在一起。
