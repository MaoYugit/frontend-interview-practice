## 为什么需要 ref

在第五阶段，我们将攻克 Vue 3 响应式系统中的另一个明星 API —— **`ref`**。

在手写 `ref` 之前，我们必须首先在理论上彻底理清一个最核心的问题：**既然已经有了强大的 `reactive`，为什么 Vue 3 还需要额外设计一个 `ref`？**

这背后主要有两个层面的原因：一个是 **JavaScript 语言特性的限制（Proxy 的局限性）**，另一个是 **值传递与引用传递的本质区别** [1]。

---

### 原因一：`Proxy` 只能代理“对象”，无法代理“原始值”

在第一阶段我们了解到，`reactive` 的底层是基于 ES6 的 `Proxy` 实现的。

然而，`Proxy` 的构造函数对入参有着极其严格的限制：**它的目标对象（Target）必须是一个非 null 的对象（包括 Object、Array、Map、Set 等），绝对不能是原始类型的值（Primitive Values）**。

如果你强行尝试用 `Proxy` 去代理一个字符串或数字：
```javascript
// ❌ 报错：TypeError: Cannot create proxy with a non-object as target
const proxyNum = new Proxy(100, {
  get(target, key) {
    return target[key];
  }
});
```
由于 JavaScript 语言标准限制了 `Proxy` 无法拦截原始值，这就意味着 **`reactive` 天然无法对数字（Number）、字符串（String）、布尔值（Boolean）、Symbol 等原始数据类型进行拦截和代理** [1]。

---

### 原因二：JavaScript 的“按值传递（Pass by Value）”特性

即使我们不报错，原始值在 JavaScript 中还有一个致命的物理特性：**它是按值传递的，而不是按引用传递的。**

请看下面这段基础代码：
```javascript
let count = 1;

function printCount(val) {
  // 这里的 val 只是数字 1 的一份拷贝，它和外面的 count 变量已经断开了联系
  console.log(val); 
}

printCount(count);

// 即使我们此后修改了 count，printCount 内部也永远无法得知这个变化
count = 2; 
```
由于原始类型不具备引用的特性，当我们将它传递给其他函数（例如传递给 `effect`、`computed` 或者是子组件）时，传递的只是一个**值拷贝**。
一旦发生拷贝，数据的变化就再也无法被追踪。

---

### 解决方案：如何用 `ref` 破局？

既然原始值无法被 `Proxy` 代理，又无法在传递时保持引用，Vue 3 的破局思路其实非常朴素且有效：
> **既然原始值自己不行，那我们就用一个“外壳对象”把这个原始值包裹（wrap）起来** [1]。

```javascript
// 伪代码：ref 的本质就是包装
const countRef = {
  value: 1 // 用 .value 属性来承载真实的原始值
};
```

1.  **保留引用**：因为 `countRef` 现在是一个对象，我们把它在函数之间传递时，传递的是这个对象的**引用**。
2.  **实现拦截**：虽然我们不用 `Proxy`（因为没必要为了一个只有一个属性的对象去创建 Proxy，开销太大），但我们可以利用 JS 对象的 **Getter 和 Setter** 属性器，来拦截对 `.value` 属性的读写操作 [1]。

这就是 `ref` 诞生的根本原因：**为了让原始值类型也能拥有响应式能力，我们必须将其包装成一个包含 `.value` 属性的“Ref 引用对象”，并利用拦截器监听 `.value` 的读写。** [1]

---

### 总结与过渡

*   **`reactive`**：适用于**对象类型**，利用 `Proxy` 代理整个对象 [1]。
*   **`ref`**：适用于**任意类型**（特别是原始值），通过包裹成一个含有 `.value` 的专属 Class 实例，并利用属性拦截器（Getter/Setter）实现响应式 [1]。

明确了这层设计初衷后，下一小节我们将动手编写代码：**利用 ES6 Class 的 getter 和 setter 亲手实现 `ref`**，你会发现它的实现方式比 `reactive` 更加轻量且直观。

## 利用 Class 实现 ref

在第五阶段的第二部分，我们将使用 ES6 `Class`（类）来亲手实现 `ref`。

正如上一小节分析的，`ref` 实际上就是一个包含 `.value` 属性的“包装对象” [1]。为了拦截对 `.value` 的读写，最标准且优雅的做法就是使用 Class 的 `get` 和 `set` 访问器（Accessors） [1]。

另外，这里有一个非常精妙的设计对比：
*   **`reactive`** 的数据结构非常复杂，需要用 `targetMap (WeakMap)` 顺着对象和 Key 艰难地寻找依赖集合。
*   **`ref`** 却极其纯粹！因为一个 `ref` 实例有且仅有一个属性 `.value`，所以**每个 `ref` 实例可以直接在其内部持有一个专属的 `dep`（Set 集合）** [1]。这不仅让代码更加轻量，也让 `ref` 的依赖收集和触发速度极快！

---

### 1. 核心代码实现

新建一个 `ref.js`：

```javascript
import { activeEffect, trackEffects, triggerEffects } from './effect.js';
import { reactive } from './reactive.js';

// 辅助函数：判断是否为对象
function isObject(val) {
  return val !== null && typeof val === 'object';
}

// 辅助函数：判断值是否真的发生了变化（规避 NaN !== NaN 的干扰）
function hasChanged(value, oldValue) {
  return !Object.is(value, oldValue);
}

// 🌟 标准处理：如果传入 ref 的是一个对象，Vue 3 底层会调用 reactive 将其转化为响应式 Proxy
function toReactive(value) {
  return isObject(value) ? reactive(value) : value;
}

class RefImpl {
  constructor(value) {
    // 1. 保存最原始的值，方便后续在 set 时进行新旧比对
    this._rawValue = value;
    
    // 2. 如果传入的是个对象，则使用 toReactive 处理，使其具备深度响应式
    this._value = toReactive(value);

    // 🌟 核心设计：每个 ref 实例直接在内部持有自己唯一的 dep Set
    this.dep = new Set();

    // 暗号标记：用来识别这是一个 Ref 实例
    this.__v_isRef = true;
  }

  // 拦截读取：obj.value
  get value() {
    // 1. 只有当处于 effect 运行环境中（activeEffect 有值），才进行依赖收集
    if (activeEffect) {
      // 直接复用我们在第三阶段封装的 trackEffects 方法！
      trackEffects(this.dep);
    }
    return this._value;
  }

  // 拦截设置：obj.value = newVal
  set value(newVal) {
    // 1. 只有在新旧值确实发生改变时，才进行更新
    if (hasChanged(newVal, this._rawValue)) {
      // 更新原始值记录
      this._rawValue = newVal;
      // 更新包装值（同样通过 toReactive 保证如果设置新值为对象时能正常代理）
      this._value = toReactive(newVal);

      // 2. 触发更新：直接复用在第三阶段封装的 triggerEffects 方法！
      triggerEffects(this.dep);
    }
  }
}

/**
 * 创建 ref 响应式数据
 * @param {*} value 原始值或对象
 */
export function ref(value) {
  return new RefImpl(value);
}
```

---

### 2. 编写测试用例验证

我们通过一段代码，同时测试 **原始值的 ref 响应式**，以及 **ref 包裹对象时的深度响应式能力**。

```javascript
import { ref } from './ref.js';
import { effect } from './effect.js';

console.log('--- 1. 测试原始值的 ref 响应式 ---');
const count = ref(10);

effect(() => {
  console.log(`[Effect 1] count 的值变更为: ${count.value}`);
});
// 首次输出: [Effect 1] count 的值变更为: 10

console.log('\n--- 修改 count.value ---');
count.value = 20;
// 预期输出: [Effect 1] count 的值变更为: 20


console.log('\n--- 2. 测试对象的 ref 响应式 ---');
// 如果传入对象，RefImpl 会自动将其调用 reactive(obj) 转化为 Proxy
const user = ref({ name: 'Bob' });

effect(() => {
  // 读取深层属性，触发 Proxy 的 get 以及 ref 的 get
  console.log(`[Effect 2] 用户名字是: ${user.value.name}`);
});
// 首次输出: [Effect 2] 用户名字是: Bob

console.log('\n--- 修改 user.value.name ---');
user.value.name = 'Alice';
// 预期输出: [Effect 2] 用户名字是: Alice
```

---

### 总结

到目前为止，我们已经用最干练、核心的代码实现了 `ref`：
1.  **直接持有 `dep`**：省去了像 `reactive` 一样复杂的 `targetMap` 查表步骤，直接在 `this.dep` 上做文章 [1]。
2.  **调用复用**：无缝复用了我们之前在 `track` 和 `trigger` 阶段抽象出来的 `trackEffects` 和 `triggerEffects`，体现了高内聚的代码设计 [1]。
3.  **支持对象**：通过 `toReactive` 的无缝衔接，使 `ref` 不仅能处理原始值，还能无痛兼容对象类型。

现在，核心的 `reactive` 和 `ref` 全部大功告成！

## 相关辅助函数

在第五阶段的第三部分，我们将实现 Vue 3 中围绕 `ref` 设计的几个高频实用辅助函数：`isRef`、`unref`、`toRef` 与 `toRefs`。

理解并手写这些函数，不仅能让你明白 Vue 3 中响应式数据是如何进行类型转换的，更能帮你解答一个经典面试题：**“为什么解构 reactive 对象会丢失响应式，而 toRefs 可以解决这个问题？”** [1]

---

### 1. 核心辅助函数实现

我们可以直接将这些辅助函数写在 `ref.js` 中：

#### (1) `isRef`
*   **作用**：判断一个值是否是 `ref` 对象。
*   **原理**：检查该值是否为对象，且其身上是否带有我们之前埋下的“暗号标记” `__v_isRef === true` [1, 2]。

```javascript
export function isRef(r) {
  return !!(r && r.__v_isRef === true);
}
```

#### (2) `unref`
*   **作用**：获取 `ref` 的内部真实值。如果传入的是 `ref`，返回 `r.value`；如果传入的是普通值，则直接返回该值本身 [1, 2]。
*   **原理**：利用 `isRef` 进行判断。

```javascript
export function unref(r) {
  return isRef(r) ? r.value : r;
}
```

#### (3) `toRef`
*   **作用**：将响应式对象（`reactive`）的某个属性，单独提取出来包装成一个 `ref` 引用，且**与源属性保持双向同步** [1]。
*   **实现思路**：我们不直接创建完整的 `RefImpl`（那会复制一份数据），而是创建一个轻量级的代理类 `ObjectRefImpl` [1]。它的 `get value` 和 `set value` 会直接去读写原 `reactive` 对象的对应属性，从而完美借用原对象的响应式能力 [1]。

```javascript
class ObjectRefImpl {
  constructor(object, key) {
    this._object = object;
    this._key = key;
    this.__v_isRef = true; // 依然是 ref 实例
  }

  get value() {
    // 代理读取：实际上读取的是原 reactive 对象的属性，从而触发原对象的 get/track
    return this._object[this._key];
  }

  set value(newVal) {
    // 代理写入：实际上修改的是原 reactive 对象的属性，从而触发原对象的 set/trigger
    this._object[this._key] = newVal;
  }
}

export function toRef(object, key) {
  // 如果该属性本来就是个 ref，直接返回它
  if (isRef(object[key])) {
    return object[key];
  }
  // 否则，创建一个轻量级的属性代理 Ref
  return new ObjectRefImpl(object, key);
}
```

#### (4) `toRefs`
*   **作用**：将一个响应式对象（`reactive`）的所有属性，转换为一个普通对象，该普通对象的每个属性都是一个指向源对象对应属性的 `ref` [1]。
*   **核心痛点**：在 ES6 中，如果我们直接解构一个 `reactive` 对象（例如 `const { name } = reactive({ name: 'Bob' })`），解构出来的 `name` 只是一个普通的字符串字面量，**会彻底失去响应式** [1]。而 `toRefs` 就是为了解决解构不丢失响应式而生的 [1]。

```javascript
export function toRefs(object) {
  // 支持数组和对象的转换
  const res = Array.isArray(object) ? new Array(object.length) : {};
  
  for (const key in object) {
    // 遍历每一个 key，将其转化为代理 ref
    res[key] = toRef(object, key);
  }
  
  return res;
}
```

### 2. 实战测试：验证 `toRefs` 解决解构响应式丢失问题

让我们编写测试脚本，亲自验证 `toRefs` 的工作原理：

```javascript
import { reactive } from './reactive.js';
import { toRefs } from './ref.js';
import { effect } from './effect.js';

// 1. 创建一个普通的 reactive 响应式对象
const user = reactive({
  name: 'Alice',
  age: 18
});

// 2. ❌ 错误示范：如果直接解构，name 和 age 会变成普通变量，失去响应式
// const { name, age } = user; 

// 3. 🌟 正确示范：使用 toRefs 转换后再进行解构
const { name, age } = toRefs(user); 
// 此时，name 和 age 分别是代理了 user.name 和 user.age 的 ObjectRefImpl 实例

effect(() => {
  // 必须通过 .value 进行读取
  console.log(`[DOM 更新] 用户名字: ${name.value}, 年龄: ${age.value}`);
});
// 首次同步输出: [DOM 更新] 用户名字: Alice, 年龄: 18

console.log('\n--- 场景 A：直接修改解构后的 ref.value ---');
name.value = 'Bob'; 
// 预期输出: [DOM 更新] 用户名字: Bob, 年龄: 18
console.log('原 reactive 对象的值是否同步变了？', user.name); 
// 预期输出: 原 reactive 对象的值是否同步变了？ Bob

console.log('\n--- 场景 B：修改原 reactive 对象的值 ---');
user.age = 20; 
// 预期输出: [DOM 更新] 用户名字: Bob, 年龄: 20
console.log('解构出的 ref.value 是否同步变了？', age.value);
// 预期输出: 解构出的 ref.value 是否同步变了？ 20
```

### 总结

*   **`isRef` 与 `unref`**：提供了极佳的安全访问保障，在 Vue 源码的很多地方（比如模板解析、`setup` 返回值解析时）被广泛用于自动脱 `ref`（Auto-unwrapping） [1, 2]。
*   **`toRef` 与 `toRefs`**：作为 `reactive` 和 `ref` 之间的桥梁，提供了一种不丢失响应式的属性引用机制，优雅地解决了 ES6 解构语法带来的副作用 [1]。

至此，第五阶段所有内容全部闭环！你已经拥有了一个支持 `reactive`、`ref` 及其周边辅助函数的精简版响应式系统。
