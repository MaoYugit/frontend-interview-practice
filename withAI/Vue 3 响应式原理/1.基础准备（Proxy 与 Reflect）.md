## Vue 2 与 Vue 3 响应式实现方式的区别

理解 Vue 2 与 Vue 3 响应式原理的区别，是掌握现代前端框架演进的重要一步。这两者的核心区别在于**拦截数据变化的时机与维度不同**：Vue 2 是**属性级别**的拦截，而 Vue 3 是**对象级别**的拦截。

下面我们一起来详细对比一下这两者底层的实现方式、优缺点以及它们在实际开发中的表现。

---

### 一、 Vue 2 的响应式基础：`Object.defineProperty`

在 Vue 2 中，响应式是通过 `Object.defineProperty` 静态地重写对象的属性来实现的。

#### 1. 工作原理
Vue 2 在初始化数据（如 `data`）时，会遍历对象的所有属性，并使用 `Object.defineProperty` 把这些属性全部转为 `getter/setter`。

简易原理代码：
```javascript
function defineReactive(obj, key, val) {
  // 如果 val 也是对象，需要递归遍历，使其也变成响应式
  observe(val); 

  Object.defineProperty(obj, key, {
    get() {
      // 依赖收集（收集当前的 Dep.target）
      console.log(`获取属性 ${key}: ${val}`);
      return val;
    },
    set(newVal) {
      if (newVal !== val) {
        console.log(`属性 ${key} 被修改为: ${newVal}`);
        val = newVal;
        observe(newVal); // 新值如果是对象，也需要转化为响应式
        // 触发更新
      }
    }
  });
}

function observe(obj) {
  if (typeof obj !== 'object' || obj === null) return;
  Object.keys(obj).forEach(key => {
    defineReactive(obj, key, obj[key]);
  });
}
```

#### 2. `Object.defineProperty` 的优缺点

*   **优点**：
    *   **浏览器兼容性极佳**：支持 IE9 及以上浏览器。在 Vue 2 诞生的年代（2013-2014年），IE 浏览器仍占有不小的市场份额，这个特性是当时实现响应式的最佳选择。

*   **缺点/痛点**：
    1.  **无法检测到对象属性的新增和删除**：
        由于它只能对**已有属性**进行拦截，如果对象初始化后你动态添加了新属性（如 `obj.newKey = 'value'`），或者删除了属性（`delete obj.key`），Vue 2 是无法感知到的。为了解决这个问题，官方不得不提供了 `this.$set` 和 `this.$delete` 这样的补丁 API。
    2.  **对数组的支持不完美**：
        `Object.defineProperty` 理论上可以拦截数组索引的变化，但由于数组长度可能非常大，遍历监听每一个索引的性能开销难以接受。因此，Vue 2 放弃了对数组索引的直接监听，转而通过**改写/劫持数组的原生方法**（如 `push`, `pop`, `splice` 等 7 个方法）来实现数组的响应式。这意味着直接修改 `arr[0] = newValue` 或修改 `arr.length` 是无法触发页面更新的。
    3.  **初始化性能开销大（递归遍历）**：
        如果 `data` 里的对象嵌套非常深，Vue 2 会在初始化时一次性递归遍历该对象的所有层级，将所有属性都转为 `getter/setter`。即使某些数据在页面渲染时根本用不到，也会进行这部分计算，造成不必要的初始化耗时。

---

### 二、 Vue 3 的响应式基础：`Proxy`

Vue 3 彻底放弃了 `Object.defineProperty`，改用 ES6 的 `Proxy`（代理）来重构响应式系统。

#### 1. 工作原理
`Proxy` 并不直接修改原对象，而是在目标对象前架设一层“拦截”。无论你对该对象进行什么操作（读取、写入、删除、判断存在等），都必须先通过这层拦截。

简易原理代码：
```javascript
function reactive(target) {
  if (typeof target !== 'object' || target === null) return target;

  return new Proxy(target, {
    get(target, key, receiver) {
      console.log(`拦截获取属性: ${key}`);
      const res = Reflect.get(target, key, receiver);
      
      // 关键：惰性代理/懒代理
      // 只有在用户真正访问到深层属性时，才会将其转化为 Proxy 代理
      if (typeof res === 'object' && res !== null) {
        return reactive(res); 
      }
      return res;
    },
    set(target, key, value, receiver) {
      const oldValue = target[key];
      const result = Reflect.set(target, key, value, receiver);
      if (oldValue !== value) {
        console.log(`拦截设置属性: ${key} -> ${value}`);
        // 触发更新
      }
      return result;
    },
    deleteProperty(target, key) {
      console.log(`拦截删除属性: ${key}`);
      return Reflect.deleteProperty(target, key);
    }
  });
}
```

#### 2. `Proxy` 的优缺点

*   **优点**：
    1.  **完美支持对象属性的新增和删除**：
        因为 `Proxy` 代理的是整个对象，而不是对象的具体属性，因此不管是修改已有属性，还是直接新增属性（如 `obj.newKey = 'xxx'`）、删除属性（`delete obj.key`），都能被拦截器捕获并触发更新，从而告别了 `this.$set`。
    2.  **原生且完美支持数组及集合类型**：
        `Proxy` 可以直接拦截数组的索引赋值、长度修改，同时也完美支持了 ES6 的 `Map`、`Set`、`WeakMap`、`WeakSet` 等集合类型。
    3.  **惰性/懒代理带来的性能提升**：
        Vue 3 在初始化一个深度嵌套的对象时，**不会**一次性递归把所有后代对象都变成响应式。它只代理最外层。只有当你真正读取到深层的某个对象（触发 `get`）时，Vue 3 才会动态地把该深层对象包装成 Proxy。这极大地减少了初次渲染时的内存开销和计算耗时。
    4.  **提供多达 13 种拦截方法**：
        除了 `get` 和 `set`，还可以拦截 `has` (判断 key 是否存在)、`ownKeys` (获取属性列表) 等。这使得响应式系统能够进行更精准、更多维度的依赖收集。

*   **缺点/限制**：
    1.  **浏览器兼容性限制（无法完全 Polyfill）**：
        `Proxy` 是 ES6 引入的底层特性，它是由浏览器引擎直接原生支持的。这意味着它**无法通过 Babel 等工具完全模拟/降级（Polyfill）**。因此，Vue 3 无法运行在不支持 `Proxy` 的旧版浏览器（如 IE11 及以下）中。

---

### 三、 总结与对比表

| 对比维度              | Vue 2 (`Object.defineProperty`)                  | Vue 3 (`Proxy`)                               |
| :-------------------- | :----------------------------------------------- | :-------------------------------------------- |
| **拦截维度**          | **属性级别**（必须知道具体的 Key 才能拦截）      | **对象级别**（代理整个对象，一劳永逸）        |
| **动态新增/删除属性** | ❌ 不支持（需使用 `Vue.set` / `Vue.delete`）      | 支持（直接操作即可触发响应式）                |
| **数组支持**          | ⚠️ 局限（需重写数组原型方法，无法监听索引和长度） | 完美支持（无需特殊处理）                      |
| **Map / Set 支持**    | ❌ 不支持                                         | 完美支持                                      |
| **深度监听机制**      | ⚠️ 初始化时**一次性递归**，性能开销大             | **惰性代理**（访问到哪一层，代理到哪一层）    |
| **兼容性**            | 好（支持 IE9+）                                  | ⚠️ 差（不支持 IE11 及以下，且无法被 Polyfill） |

### 结语
Vue 3 选择用 `Proxy` 取代 `Object.defineProperty`，虽然牺牲了极少数老旧浏览器的兼容性，但换来的是**更清爽的 API 体验（再也不用写 $set）**、**大幅提升的初始化性能**以及**更强大的数据结构支持**。这也是现代前端开发全面拥抱现代浏览器标准的一个典型范例。

## Proxy 的基本用法

在这一部分，我们来学习如何使用 ES6 的 `Proxy`（代理）来拦截对象的读取（`get`）和写入（`set`）操作。

在 JavaScript 中，`Proxy` 就像是一个“经纪人”或“防火墙”。你不能直接操作目标对象，而是必须通过这个“经纪人”，这就给了我们在操作发生时进行干预的机会。

---

### 1. Proxy 的基本语法

创建一个代理对象的语法非常简单：

```javascript
const proxy = new Proxy(target, handler);
```

*   **`target`（目标对象）**：你想要代理的原始对象（可以是对象、数组、甚至是函数）。
*   **`handler`（处理器对象）**：一个定制了各种拦截行为（陷阱，Traps）的对象。

要拦截 `get` 和 `set` 操作，我们需要在 `handler` 中定义对应的 `get` 和 `set` 函数。

---

### 2. 拦截 `get` 操作

`get` 陷阱用于拦截对象属性的**读取**操作。

#### 函数签名：
```javascript
get(target, prop, receiver)
```
*   **`target`**：目标对象（即被代理的原始对象）。
*   **`prop`**：被读取的属性名（字符串或 Symbol）。
*   **`receiver`**：Proxy 实例本身（或者继承自 Proxy 的对象）。

#### 示例代码：
```javascript
const user = { name: '张三', age: 18 };

const proxyUser = new Proxy(user, {
  get(target, prop, receiver) {
    console.log(`[Get] 正在读取属性: "${prop}"`);
    
    // 如果读取的属性不存在，我们可以给一个默认值，而不是返回 undefined
    if (!(prop in target)) {
      return '未知属性';
    }
    
    return target[prop];
  }
});

// 测试
console.log(proxyUser.name); 
// 输出: 
// [Get] 正在读取属性: "name"
// 张三

console.log(proxyUser.gender); 
// 输出: 
// [Get] 正在读取属性: "gender"
// 未知属性
```

---

### 3. 拦截 `set` 操作

`set` 陷阱用于拦截对象属性的**设置/修改/新增**操作。

#### 函数签名：
```javascript
set(target, prop, value, receiver)
```
*   **`target`**：目标对象。
*   **`prop`**：要写入的属性名。
*   **`value`**：要写入的新值。
*   **`receiver`**：通常是 Proxy 实例本身。

> ⚠️ **重要规范**：`set` 陷阱必须返回一个布尔值（`true` 或 `false`）。
> * 返回 `true` 代表属性设置成功。
> * 返回 `false`（或者不返回值）代表属性设置失败。在 JavaScript 的**严格模式**（`"use strict"`）下，如果 `set` 拦截器返回 `false`，会直接抛出 `TypeError` 异常。

#### 示例代码（带数据验证）：
```javascript
const user = { name: '张三', age: 18 };

const proxyUser = new Proxy(user, {
  set(target, prop, value, receiver) {
    console.log(`[Set] 正在尝试设置属性 "${prop}" 为: ${value}`);

    // 我们可以在这里进行数据校验
    if (prop === 'age') {
      if (typeof value !== 'number' || value < 0) {
        console.warn('年龄必须是大于0的数字');
        return false; // 设置失败
      }
    }

    // 将值写入原始对象
    target[prop] = value;
    return true; // 必须返回 true 表示设置成功
  }
});

// 测试修改已存在属性
proxyUser.age = 20; // 成功

// 测试数据校验不通过
proxyUser.age = -5; // 警告：年龄必须是大于0的数字（在严格模式下此处会报错）

// 测试新增属性
proxyUser.gender = '男'; // 成功

console.log(user); 
// 输出原始对象: { name: '张三', age: 20, gender: '男' }
```

---

### 4. 结合 Vue 3 响应式理解

在 Vue 3 的响应式系统中，`get` 和 `set` 承担了最核心的工作：

*   **在 `get` 中进行“依赖收集”（Track）**：
    当视图（例如模板、computed、watch）读取某个响应式数据时，会触发 `get`。Vue 3 会在这个时候把当前正在渲染的视图（Effect）记录下来，这就是“**谁用到了这个数据，我就把谁记在本子上**”。
*   **在 `set` 中进行“派发更新”（Trigger）**：
    当用户修改数据时，会触发 `set`。Vue 3 会在这个时候翻开刚才的“本子”，找到所有依赖这个属性的视图（Effect），并让它们重新执行一遍，这就是“**数据变了，我通知刚才记下的人去更新视图**”。

你可以把上面的示例代码当作一个雏形。在接下来的小节里，我们会看到为什么不能直接使用 `target[prop]` 来读取和写入，而必须引入 `Reflect`，这是手写响应式系统时非常关键的一步。

---

## 为什么 Proxy 必须配合 Reflect 使用

在手写 Vue 3 响应式时，**“为什么 Proxy 必须要配合 Reflect 使用”** 是一个高频面试题，也是理解响应式系统底层细节的难点。

简单来说：**如果不配合 `Reflect`，在面对存在继承关系或包含 `this` 读取的对象时，Vue 3 的依赖收集机制将会失效。**

下面我们通过拆解 `Reflect` 的基本 API 和深入剖析 `this` 指向问题，来彻底搞懂这个设计。

---

### 一、 理解 `Reflect` 及其基本 API

`Reflect` 是 ES6 引入的一个内置对象，它提供了一系列与 `Proxy` 拦截方法**一一对应**的静态方法。

#### 1. 为什么叫“一一对应”？
`Proxy` 的 `handler` 里能写什么拦截方法，`Reflect` 上就有同名的静态方法。
*   `Proxy` 的 `get(target, prop, receiver)`  对应  `Reflect.get(target, prop, receiver)`
*   `Proxy` 的 `set(target, prop, value, receiver)` 对应 `Reflect.set(target, prop, value, receiver)`

#### 2. Reflect 的设计目的之一：更优雅、标准的返回值
在没有 `Reflect` 之前，我们修改属性是用 `obj[key] = value`，这如果失败了不会有明显的返回值（在严格模式下甚至直接报错）。
而 `Reflect.set` 会返回一个布尔值，告诉你操作是否成功，这非常契合 `Proxy` 拦截器需要返回布尔值的规范。

```javascript
const obj = {};
// 传统写法
obj.a = 1; // 无法直接知道是否成功

// Reflect 写法
const isSuccess = Reflect.set(obj, 'a', 1); 
console.log(isSuccess); // true
```

---

### 二、 核心问题：`this` 指向偏离（不配合 Reflect 的后果）

这是使用 `Reflect` 的最关键原因。我们来看一个包含 `get` 属性（Getter）的对象。

#### 1. 准备一个带 Getter 的目标对象
```javascript
const user = {
  firstName: '张',
  lastName: '三',
  // fullName 是一个 getter，内部使用了 this
  get fullName() {
    return this.firstName + this.lastName;
  }
};
```

#### 2. 场景 A：不使用 Reflect（只用 `target[key]`）
如果我们像下面这样编写代理，直接通过 `target[key]` 返回属性：

```javascript
const proxyUser = new Proxy(user, {
  get(target, key, receiver) {
    console.log(`[Get拦截] 读取了属性: "${key}"`);
    return target[key]; // 直接通过 target 获取
  }
});

// 测试读取 fullName
console.log(proxyUser.fullName);
```

**运行结果：**
```text
[Get拦截] 读取了属性: "fullName"
张三
```

**⚠️ 致命问题分析：**
为什么只打印了 `[Get拦截] 读取了属性: "fullName"`？
`fullName` 内部明明读取了 `this.firstName` 和 `this.lastName`，为什么**没有**触发 `firstName` 和 `lastName` 的拦截？

*   **原因**：当我们执行 `proxyUser.fullName` 时，进入了拦截器的 `get`。此时 `target` 是原对象 `user`。
*   `target[key]` 相当于执行了 `user.fullName`。
*   在执行 `user.fullName` 的 getter 函数时，**`this` 指向的是原对象 `user`**，而不是代理对象 `proxyUser`。
*   因此，`this.firstName` 实际上是 `user.firstName`，它直接绕过了代理对象。
*   **后果**：Vue 3 无法收集到 `fullName` 对 `firstName` 和 `lastName` 的依赖。以后如果修改了 `firstName`，页面将**不会**发生更新！

---

### 三、 解决方案：使用 `Reflect` 传入 `receiver`

为了解决 `this` 指向偏离的问题，`Proxy` 的 `get` 和 `set` 陷阱中提供了一个参数叫 `receiver`。
*   **`receiver` 的本质**：它代表的是**代理对象本身**（在上面的例子中，就是 `proxyUser`）。

当我们把 `receiver` 传给 `Reflect.get(target, key, receiver)` 时，`Reflect` 会在底层做一件事：**将 getter 函数内部的 `this` 强制绑定为 `receiver`（即代理对象）。**

#### 场景 B：配合 Reflect 使用

```javascript
const proxyUserCorrect = new Proxy(user, {
  get(target, key, receiver) {
    console.log(`[Get拦截] 读取了属性: "${key}"`);
    // 将 receiver（即当前的代理对象）传递给 Reflect
    return Reflect.get(target, key, receiver);
  }
});

// 测试读取 fullName
console.log(proxyUserCorrect.fullName);
```

**运行结果：**
```text
[Get拦截] 读取了属性: "fullName"
[Get拦截] 读取了属性: "firstName"
[Get拦截] 读取了属性: "lastName"
张三
```

**🎉 结果说明：**
*   由于传入了 `receiver`，`fullName` 内部的 `this` 被指向了 `proxyUserCorrect`。
*   当它执行 `this.firstName` 时，等同于执行 `proxyUserCorrect.firstName`。
*   这样就顺利地再次触发了 `get` 拦截，完成了 `firstName` 和 `lastName` 的依赖收集。

---

### 四、 总结

在手写 Vue 3 响应式时，`Proxy` 和 `Reflect` 是无法分割的搭档。

1.  **`Proxy`** 负责建立一层“拦截网”，捕捉用户的各种操作（读、写、删等）。
2.  **`Reflect`** 负责将操作高效、标准地“转发”给原对象，同时通过传入 `receiver` 参数，**确保对象内部（如 Getter/Setter）的 `this` 始终指向代理对象**，从而保证依赖收集（Track）和派发更新（Trigger）的完整性。

这也是为什么在 Vue 3 源码中，所有 `Proxy` 拦截操作的底层一律使用 `Reflect` 的根本原因。
